Rejection Reasons are master data values used in donor-related workflows when a donor needs to be rejected. This module helps the team maintain a structured list of rejection reasons that can be selected whenever rejection is required.

![Rejection Reason listing page](/screens/master-data/rejection-reason/DonorRejection_Listing.png)

## Overview

The Rejection Reason module is used to manage all donor rejection reasons in one place.

From this page, users can:

- view all rejection reasons in a table
- add a new rejection reason
- edit an existing rejection reason
- change the status of a rejection reason
- delete a rejection reason when it is no longer needed

This keeps rejection reason information organized and makes it easier to use during donor rejection workflows.

## Purpose

The main purpose of this module is to store and maintain rejection reasons in a standard format.

Instead of typing the rejection reason manually each time, staff can select a saved reason from the list. This reduces mistakes and keeps the workflow consistent.

## Page Layout

The Rejection Reason page shows a simple listing view with the main details needed for daily work.

Typical columns include:

- Code
- Reason
- Description
- Status
- Actions

### Field Guide

| Field | Description |
| --- | --- |
| **Code** | Auto-generated code for the rejection reason. |
| **Reason** | Rejection reason name. |
| **Description** | Short explanation of the reason. |
| **Status** | Shows whether the reason is active or inactive. |

The page also includes an **Add Reason** button for creating a new rejection reason.

Each row contains action buttons that let users edit or delete the reason as needed.

## Actions Available

Each rejection reason row supports the following actions:

- **Edit** - update the reason name, description, or status
- **Delete** - remove a reason when it is no longer needed
- **Status** - review whether the reason is active or inactive

These actions help users maintain the list without leaving the page.

## Add Rejection Reason

Use this option when a new rejection reason needs to be added to the system.

### Steps to Add Rejection Reason

1. Open the **Rejection Reason** page.
2. Click **Add Reason**.
3. Enter the rejection reason name.
4. Enter a short description.
5. Review the details carefully.
6. Save the record.

### What users should enter

- **Code** - this is auto-generated by the system
- **Reason** - enter the rejection reason name
- **Description** - enter a short explanation of the reason
- **Status** - set to active when the reason should be available for use

After saving, the new rejection reason appears in the listing and becomes available wherever rejection reasons are used.

![Add Rejection Reason form](/screens/master-data/rejection-reason/DonorRejection_Add.png)

## Edit Rejection Reason

Use the edit option when an existing rejection reason needs to be corrected or updated.

### Steps to Edit Rejection Reason

1. Find the required rejection reason in the list.
2. Click the **Edit** button.
3. Update the reason name if needed.
4. Update the description if needed.
5. Change the status if required.
6. Review the changes.
7. Save the record.

Editing is useful when the reason text needs correction, the description needs to be improved, or the status must be changed.

![Edit Rejection Reason form](/screens/master-data/rejection-reason/DonorRejection_Edit.png)

## Status Handling

Rejection reasons can be in one of two states:

- **Active**
- **Inactive**

### Active

An active rejection reason is available for selection during donor rejection workflows.

### Inactive

An inactive rejection reason is not shown in operational selection lists, so staff cannot choose it in daily workflows.

This helps the team keep only valid and usable rejection reasons available.

## Delete Behavior

If a rejection reason is no longer needed, it can be deleted from the module.

### What happens when a reason is deleted

- a confirmation popup appears first
- the user must confirm the action
- after confirmation, the reason is removed from the listing
- deleted rejection reasons should no longer be used in future workflows

This prevents old or unused rejection reasons from being selected by mistake.

![Delete Rejection Reason confirmation](/screens/master-data/rejection-reason/DonorRejection_Delete.png)

## Used In

Rejection reasons are used in donor workflows where a donor must be rejected.

This may include rejection dialogs or donor status actions inside the blood bank system.

Using a saved rejection reason list keeps donor rejection information consistent and easy to reuse.

![Rejection reason usage in donor workflow](/screens/master-data/rejection-reason/DonorRejection_UsageinDonor.png)

## Important Notes

- Keep rejection reason names clear and easy to understand.
- Always maintain correct descriptions for each reason.
- Mark unused rejection reasons as inactive instead of leaving them active.
- Delete a rejection reason only when it is no longer needed.
- The rejection reason selected in a workflow becomes part of the related donor record.
